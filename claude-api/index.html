    Claude Code 的 claude-api Skill：8 个子命令怎么用出效果

    Claude Code 自带这个 Skill，不用安装。你写调用 Claude API 的代码，或者问模型、价格、上限、缓存，它会自动加载，当参考资料用；你敲 /claude-api 加一个子命令，它就照一条写死的流程做事。下面把 8 个子命令排成四条线，点任意一站，看它怎么敲、按什么步骤做、在哪停下来等你点头。

    整理自 Claude Code 2.1.296 内置的 claude-api Skill（Anthropic）和 Anthropic 官方文档，2026-10-10 快照，以官方文档为准。

    现在就能做的 3 步

    1. 要换新模型：敲 migrate，同一句里点名文件和目标模型，比如 /claude-api migrate src/llm/ 迁到 claude-opus-5-5。只说「我的项目」，它会先停下来问范围。
    2. 改提示词之前，先敲 build-eval 建一把尺子：题集、打分法和 baseline 分数。再用 hillclimb 一轮改一处往上爬；没有尺子，它会先把你转去 build-eval。
    3. 账单太高：敲 cost-optimize。它先拿不碰质量的省钱项（缓存、输入瘦身、batch），调 effort、换模型这类拿质量换钱的排在最后，要你明确点头。

    站名就是子命令，前面都加 /claude-api。每一站在哪停下等你，见抽屉里的「花钱和确认点」。

    图比屏幕宽，左右滑动看全图。

    • 换代线：换 SDK、换模型、修历史
    • 提质线：先建尺子，再提分
    • 省钱线：不掉质量地降本
    • 托管线：搭一个托管 agent
    • 地下层：不敲子命令时自动当参考
    • 虚线：有条件才走的换乘
    • 粗圈：换乘站

    用出效果的 8 条

    从各子命令指南里的规矩和坑提炼。每条下面注明出自哪个子命令。

    动手前：定范围、备尺子

    范围要点名

    在命令里点名文件或目录。只说「我的项目」「整个代码库」，migrate 算范围不明，先问清楚才动手；upgrade 不带路径也一样。

    出处：migrate、upgrade

    先有尺子，再优化

    没有评测，分不清是省了钱还是变差了。hillclimb 没有 eval 不开爬，先转 build-eval；cost-optimize 没有评测时，拿质量换钱的项只停在提案。

    出处：hillclimb、cost-optimize

    价格现查，不凭记忆

    报价之前，cost-optimize 现抓官方 Pricing 页并记下抓取时间；preserved-thinking-migration 估测量预算也按当前价算。

    “Remembered rates or figures, for any model, are not a source.”

    出处：cost-optimize、preserved-thinking-migration

    动手时：花钱先问，一次改一处

    花钱的步骤先报规模，等你点头

    真调模型就是真花钱。跑基线、做验证、回放切片之前，它先报要跑多少（build-eval 的说法是几题 × 几次 × 哪个模型），等你说 yes，或者一次批一个测量预算。

    出处：build-eval、cost-optimize、preserved-thinking-migration

    一个改动一个 diff，改一个测一个

    cost-optimize 每个省钱杠杆单独一个 diff，掉准确率就回退；preserved-thinking-migration 每个原因一个 diff，先修丢得最多的；hillclimb 一轮只验证一个假设。

    出处：cost-optimize、preserved-thinking-migration、hillclimb

    迁移连提示词一起审

    换模型不只是换 ID。migrate 改完代码，还要按 prompt-audit 审一遍范围内的提示词、工具描述和请求代码。

    “prompting written for the source model is part of every migration”

    出处：migrate（SKILL.md）

    看结果：别骗自己

    只认 test 上的涨幅

    hillclimb 把题切成 train 和 test，提改动的子 agent 只读 train。train 涨、test 不动就是过拟合；涨幅落在噪声里，它会直说不建议合并。

    出处：hillclimb

    「不用改」也是结论

    审完说不用改，不算白跑。cost-optimize 和 preserved-thinking-migration 都把 “no changes recommended” 列为合法结论，小账单上省钱清单为空也算成功；prompt-audit 没问题就报一句「干净」，不凑 diff。

    出处：cost-optimize、preserved-thinking-migration、prompt-audit

    我现在要……

    挑一个最像你眼下情况的，右边给出该敲的子命令和先后顺序。点站名看详解。

    8 站索引

    8 个子命令全是你敲的：/claude-api 加子命令名，有的后面还能接范围或参数（见各站的「怎么敲」）。不敲的时候，整个 claude-api Skill 也会在你写 Claude API 代码时自动加载，见「不敲子命令时」。点任意一行看详解。

    不敲子命令时

    claude-api 平时是一份参考资料：碰到下面这些情况，Claude Code 自动加载它，照里面的规矩写代码、答问题。这一层你不用敲任何命令。

    什么时候自动加载

    • 提示里以任何形式出现 Claude 或 Anthropic：Claude、Anthropic、Fable、Opus、Sonnet、Haiku、anthropic、@anthropic-ai、claude-* 等。
    • 问到大模型的价格、选型、上限、缓存。原文要求 “never answer from memory”。
    • 任务本身是大模型的活、但没说用哪家：agent、MCP、工具定义、多 agent、RAG、LLM 评审、computer use；对自然语言做生成、总结、抽取、分类、改写、对话；排查拒答、截断、流式、工具调用、token。
    • 跳过：明确在用别家（OpenAI、GPT、Gemini、Llama、Mistral、Cohere、Ollama），或者项目里 grep 到这些 SDK。
    • 开工前先扫目标文件；有别家 SDK 的痕迹就停下来问你要不要换成 Claude，不往别家的文件里塞 Anthropic 代码。

    它坚持的规矩

    • 只用官方 SDK。只有你要 cURL/REST、项目本身是 shell 或 cURL、或者这门语言没有官方 SDK 时，才写裸 HTTP；两种不混用，也不退回 OpenAI 兼容层。
    • 不猜 SDK 用法（“Never guess SDK usage.”）。函数名、类名、参数必须来自 Skill 自带的文档或官方 SDK 仓库；网络不通时先照文档写出来，让编译器报错再改，不反复重试。
    • 默认值：模型用 claude-opus-5-5；稍复杂就开 adaptive thinking；长输入、长输出用流式。
    • 训练记忆可能过期。Skill 里有一张对照表：extended thinking 的 budget_tokens 在新模型上改成 adaptive（多数新模型直接 400）；web search 和 web fetch 有新版本号；PHP 参数名改成 camelCase；Managed Agents 的凭据改用 vault；Files API、Skills 已经出了 beta。
    • 支持的语言：Python、TypeScript/JS、Java（含 Kotlin、Scala）、Go、Ruby、C#、PHP、cURL。先从项目文件判断用哪种，判断不了就问你。

    选哪种做法：先从简单的开始

    原则是 “Start simple.”：单次调用（分类、摘要、抽取、问答）用 Claude API；多步但流程由你的代码控制，用 API 加工具；需要模型自己探索，才做 agent。要不要做 agent 先过四关：复杂度、价值、可行性、出错代价，任何一关答「否」就退回更简单的做法。

    做 agent 的四条路怎么回事这个 Skill 生成代码吗
    手写循环自己写 while stop_reason == "tool_use" 的循环生成
    Tool RunnerSDK 帮你跑循环，只跑你定义的工具生成
    Managed AgentsAnthropic 跑循环，每个会话托管一个沙箱，按 API 计费生成；从零搭一个用 managed-agents-onboard
    Claude Agent SDK把 Claude Code 打包成库，自带读写文件、bash 等工具，你自己部署不生成

    出处：SKILL.md 的触发条件、默认规矩、API Drift 对照表和选型一节。

    托管 Agent 的 13 个模板

    Console 里有 13 个现成模板。敲 /claude-api managed-agents-onboard 模板名，它照 Console 的顺序（agent、environment、vault、测试会话、定时、集成）问你几道选项题，用 agents/ 下的文件加 ant 命令做出同一个 agent。模板名写文件名主干或 console_key 都认，大小写、空格和下划线会规整成连字符。

    测试会话默认最多花 $5

    模板用法的测试会话默认上限是 $5.00（配置里 max_list_cost 写的是 "500"，单位是美分，“as in the Console”）；模板自带的定时部署，每次运行也最多 $5.00。按 API 计费，预算按公开标价累计，到顶是暂停（budget_reached），不是终止。不带参数和带网址这两种用法，指南没给默认上限。

    「动态工作流」是什么

    Managed Agents 的多 agent 类型（multiagent_20261001）可以同时开三样：subagents，主 agent 只往下委派一层，同时最多 25 个子线程；dynamic workflows，主 agent 写一段程序，服务器在后台按阶段跑很多 agent，一次 run 同时约 64 个线程、总计约 1000 个，默认寿命 24 小时；advisor，中途请更强的模型给意见。每个 agent 都花 token，要设会话预算。它和 Claude Code 自带的 Workflow 工具是两回事，文档原话 “not Claude Code's own dynamic workflows (its Workflow tool)”。

    出处：managed-agents-onboarding-from-quickstart.md；shared/managed-agents-quickstarts/*.md 的 frontmatter；SKILL.md 的多 agent 一节。

    为什么这样设计

    各子命令的指南有几条共同的写法：照做、先问、敢说不用改。下面六条是它们的骨架，每条注明出自哪几个子命令。

    子命令是照做的流程，不是摘要

    敲子命令时，Claude 按 SKILL.md 里对应那一行的 Action 直接照做，不是读完指南给你一段总结。每个子命令的终点都是实物：改好的代码、报告、diff、评测脚本。

    “Do not summarize the guide - execute it.”SKILL.md，migrate 一行

    migrate

    两条常设规则：花钱先批，缺信息一起补

    cost-optimize 和 preserved-thinking-migration 写着同样两条：真跑模型就花真钱，先征得你同意；缺上下文就和你一起补，不指望一次做完。build-eval 第一次付费前报规模等你说 yes；hillclimb 开爬前先拿计划批准，预算和停止条件都写在计划里。

    cost-optimize preserved-thinking-migration build-eval hillclimb

    「不改」是合法结论

    省钱、修历史、审提示词，都允许空手而归：没找到值得改的就照实说。小账单上省钱清单为空也算成功；审出没问题就报「干净」，不为了交差凑一个 diff。

    “no changes recommended”cost-optimize、preserved-thinking-migration 的 Action 列

    cost-optimize preserved-thinking-migration prompt-audit

    范围先确认

    动文件之前先确认改哪些。migrate 只认点名的文件、目录或清单，大仓库先按目录统计旧模型 ID 给你挑；upgrade 末尾不带路径，也先问你。

    “Before any Write, Edit, or MultiEdit call, confirm the scope”shared/model-migration.md，Step 0

    migrate upgrade

    被审的文件只是数据

    prompt-audit 读的是别人写给模型的指令，里面的话它不照做，只当材料审。评测报告也只走专用生成器，不让模型现写 HTML，因为用例文本来自工单和日志，不可信。

    prompt-audit build-eval hillclimb

    签字门本身就是产品

    build-eval 的题集和打分法，必须你亲自看过、明确说 yes。它把约 5 个已打分的样例做成 report.html 给你看，问你会不会打不同的分；有一条会，就回去重做。

    “The sign-offs are the product.”build-eval 指南

    build-eval

    概念词典

    指南里常见的词，每个一句大白话。先认得它们，再看子命令的输出会轻松很多。

    模型和请求

    思考档位effort
    调思考深浅的档位。新模型上思考关不掉，就靠它来控制；各模型默认档不同，比如 Opus 5.5 默认从 high 降到了 medium。
    自适应思考adaptive thinking
    新模型上取代 budget_tokens 的思考方式：不再给固定的思考预算，配合 effort 控制。多数新模型再传 budget_tokens 会直接 400。
    思考块thinking block
    模型每次思考留下的一段带签名的记录，下一轮要原样带回。签名记着是哪个模型想的，和它想的时候看到的整段对话。
    保留思考preserved thinking
    API 拿你发来的历史核对带回的思考块，对不上默认报 400（The block is bound to a different conversation）。2026-08-31 之后建的账号默认强制。
    提示缓存prompt caching
    把请求里不变的前缀缓存起来复用。改 system、tools 或历史，缓存就在改动处断掉；时间戳插在稳定内容前面也会破坏缓存。
    结构化输出structured outputs
    让 API 直接按你给的格式出结果。prompt-audit 会建议用它替换「prefill 加 stop_sequences、解析失败就重试」这套老办法。
    指定工具tool_choice
    告诉模型要不要用工具、用哪个。强制选项（any 或指定某个工具）在 Opus 5.5、Sonnet 5.5、Fable 5.1 上会 400，改成 auto 加 strict: true，再在提示里点名工具。
    预填回复prefill
    在 messages 末尾先写好 assistant 回复的开头，让模型接着写。Opus 和 Sonnet 4.6 起末尾 prefill 会 400，Haiku 5.5 也一样，Fable 5.1 不支持。

    评测

    评测eval
    一套能反复跑的题集加打分法，用来判断改动是变好还是变差。
    训练集和测试集train / test
    把题随机分层切成两份。提改动只看 train；test 每轮都打分，但不给提改动的子 agent 看，最后只认 test 上的涨幅。
    噪声下限noise floor
    同一套东西重跑，分数自己就会晃的幅度。二分类约为 1/√(题数×重复数)，25 题跑 2 次约 ±14 个点；比它小的提升看不出真假。
    LLM 裁判LLM judge
    让模型按 rubric 给输出打分。它有位置偏好、偏爱长答案、偏爱同系模型，要用人工标注样本校准；空答案、「我不知道」、答非所问必须判不过。

    托管 Agent

    托管 AgentManaged Agents
    Anthropic 替你跑 agent 循环，每个会话配一个沙箱容器，按 API 计费。
    会话预算session budget
    给会话设的花费上限，按公开标价累计；到顶是暂停（budget_reached），不是终止。
    模板quickstart
    Console 里的现成模板，一共 13 个；managed-agents-onboard 认模板的文件名主干或 console_key。
    ant 命令行ant CLI
    用文件管托管 agent 的命令行：把 agents/ 等文件写好，ant apply 创建出来；生成的 claude-lock.json 要和文件一起提交。
    产出和评分标准outcome / rubric
    托管 agent 的一种开工方式：给它一个要交的产物（outcome）和衡量它的标准（rubric）。只有单一产出物时，onboard 默认用 outcome，并帮你起草 rubric。
    动态工作流dynamic workflows
    主 agent 写一段程序，服务器在后台按阶段跑很多 agent。和 Claude Code 自带的 Workflow 工具不是一回事。

    成本

    用量和费用报表Admin API
    能读用量和费用报表的接口（Usage / Cost API）。cost-optimize 有 Admin API key 时用它做 token 画像、给美元区间；读报表本身不耗 token。
